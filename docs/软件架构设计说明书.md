## 2. 系统概述与架构目标

### 2.1 系统概述

WorkHelper 是一款面向个人用户的离线 Windows 桌面工作台，将「任务管理、日程安排、习惯打卡、笔记记录、数据统计」集中在一个应用中。应用采用 Electron 多进程架构，界面基于 Vue 3 组件化实现，数据全部落盘到本地 SQLite 数据库，不依赖任何在线服务。

主要功能域：

| 功能域 | 说明 |
| --- | --- |
| 首页仪表盘 | 问候卡片、今日概览、日程/待办速览、近 7 天趋势、快捷入口 |
| 每日计划 | 日程、待办、重要事项、习惯打卡、专注计时与「下一个任务」推荐 |
| 分类学习模块 | 9 个主题空间（减肥运动、英语学习、剪辑学习、播客精选、表达能力、读书推荐、妆容穿搭、爆款二创、AI 学习），含目标、投入记录、模块笔记 |
| 新闻资讯 | 本地资讯条目管理，支持收藏、关键字搜索与打开外链 |
| 工作复盘 | 每日复盘日记（今日完成 / 问题与反思 / 明日计划 / 心情），按日期唯一 |
| 数据统计 | 累计指标、近 N 天趋势、习惯连续打卡、分类投入排行 |
| 设置与数据备份 | 用户昵称、数据库驱动信息、JSON 备份导出/恢复、打开数据目录 |

### 2.2 架构目标（非功能目标）

| 目标类别 | 指标 / 要求 | 设计落实手段 |
| --- | --- | --- |
| 启动速度 | 冷启动 < 3 秒 | 首帧就绪后再显示窗口（`ready-to-show`）；应用就绪时预初始化数据库；渲染层按需懒加载路由组件 |
| 资源占用 | 常驻内存 < 300MB | 单窗口；无第三方图表库（图表用纯 SVG 自绘）；查询列表统一 `LIMIT`（最多 500 条） |
| 稳定性 | 单点异常不导致进程崩溃 | IPC 处理器统一 `try/catch` 返回 `{ ok, data, error }`；数据库驱动自动回退；单实例锁避免多开竞争 |
| 数据安全 | 数据本地存储、不外传 | 全部数据写入本地 SQLite；`contextIsolation` 开启、`nodeIntegration` 关闭；CSP meta；SQL 全参数化 |
| 数据可靠性 | 断电/异常退出不损坏数据 | SQLite WAL 日志模式 + `synchronous = NORMAL`；退出时执行 `wal_checkpoint(TRUNCATE)`；导入备份使用事务 |
| 可维护性 | 分层清晰、易于扩展与测试 | 主进程/预加载/渲染/共享四层解耦；业务服务按领域拆分；共享纯函数逻辑便于单元测试 |

## 3. 总体架构

### 3.1 分层视图

应用分为四个逻辑层，依赖方向单向自顶向下（共享层可被各层引用）：

```
+--------------------------------------------------------------------------------+
|                              渲染层 Renderer                                    |
|  Vue 3 + Pinia + Vue Router(hash)  |  App.vue / views / components / stores      |
|  仅通过 window.api（contextBridge 白名单）发起请求                               |
+--------------------------------------------------------------------------------+
                                    |  window.api.*
                                    v
+--------------------------------------------------------------------------------+
|                         预加载桥接层 Preload                                    |
|  contextBridge.exposeInMainWorld('api', api)                                    |
|  封装 ipcRenderer.invoke，解包 { ok, data, error }，失败时抛出 Error             |
+--------------------------------------------------------------------------------+
                                    |  ipcRenderer.invoke / ipcMain.handle
                                    v
+--------------------------------------------------------------------------------+
|                            主进程层 Main                                        |
|  index.ts（生命周期/窗口） | ipc.ts（通道注册） | db/（连接与迁移）                 |
|  services/*.service.ts（领域业务） | dev-capture.ts（调试截图）                    |
+--------------------------------------------------------------------------------+
                                    |
                                    v
+--------------------------------------------------------------------------------+
|                            共享层 Shared                                        |
|  types.ts（数据模型/接口契约）  logic.ts（日期/进度/统计纯函数）                    |
|  被主进程与渲染层共同引用，不依赖 Electron / Node API                             |
+--------------------------------------------------------------------------------+
```

### 3.2 各层职责与依赖规则

| 层 | 目录 | 职责 | 依赖约束 |
| --- | --- | --- | --- |
| 主进程层 | `src/main` | 应用与窗口生命周期、IPC 通道注册、数据库连接与迁移、领域业务服务、调试截图 | 可依赖 Electron、Node、`src/shared`；不可依赖渲染层代码 |
| 预加载桥接层 | `src/preload` | 通过 `contextBridge` 向渲染层暴露白名单 API，统一解包主进程响应 | 仅依赖 Electron 与 `src/shared` 类型 |
| 渲染层 | `src/renderer/src` | 视图渲染、页面路由、状态管理、交互反馈 | 只能通过 `window.api` 访问主进程能力；不可直接使用 Node/Electron API |
| 共享层 | `src/shared` | 数据模型与接口契约（`types.ts`）、纯函数逻辑库（`logic.ts`） | 不依赖 Electron / Node API，可被任意层与单元测试引用 |

依赖方向是单向的：渲染层 → 预加载层 → 主进程层；共享层处于底层被所有层引用。任何反向依赖（如主进程直接引用 Vue 组件）都不被允许。

## 4. 关键技术选型与理由

| 需求维度 | 选择方案 | 备选方案 | 取舍理由 |
| --- | --- | --- | --- |
| 桌面运行时 | Electron 44.7.0 | Tauri / .NET WPF / 原生 Win32 | Electron 内置 Node 24 与 Chromium 152，Web 技术栈（Vue 3）可高度还原设计稿；生态成熟、跨能力（文件对话框、系统浏览器、单实例）开箱即用。Tauri 依赖系统 WebView2、Rust 构建链，落盘与多窗口能力更受限；WPF/原生 Win32 开发效率低、UI 还原成本高 |
| 前端框架 | Vue 3.5.43 + TypeScript 5.9.3 | React / Svelte | 组合式 API 适合组件化拆分卡片式界面；TypeScript 全链路类型约束；与 `electron-vite` 模板无缝集成 |
| 状态管理 | Pinia 4.0.3 | Vuex / 组件内状态 | 轻量、类型友好，`stores` 集中管理跨组件共享数据与异步动作 |
| 路由 | Vue Router 5.4.0（hash 模式） | history 模式 | 应用打包后以 `file://` 协议加载，hash 模式无需服务端路由回退，规避白屏 |
| 构建工具 | electron-vite 5.0.0 + Vite 7.3.7 | Webpack / 手工脚本 | 一次配置同时构建 main / preload / renderer 三目标，内置依赖外部化与热更新 |

## 5. 主进程设计

### 5.1 应用启动流程

`src/main/index.ts` 为主进程入口，启动顺序如下：

1. 读取环境变量 `WORKHELPER_DATA_DIR`，若存在则调用 `app.setPath('userData', ...)` 重定向数据目录（便携/调试用途）。
2. 调用 `app.requestSingleInstanceLock()` 申请单实例锁；未获取到锁时直接 `app.quit()`。
3. 注册 `second-instance` 事件：重复启动时还原并聚焦已有窗口。
4. 应用就绪（`whenReady`）后依次执行：
   - `app.setAppUserModelId('com.workhelper.desktop')`（Windows 任务栏分组与通知标识）；
   - `getDb()` 预初始化数据库（缩短首次操作等待）；
   - `registerIpcHandlers(() => mainWindow)` 注册全部 IPC 通道；
   - `createWindow()` 创建主窗口；
   - 注册 `activate` 事件（无窗口时重建）。
5. 注册生命周期收尾：`window-all-closed`（非 macOS 退出应用）、`will-quit`（调用 `closeDb()` 关闭数据库）。

### 5.2 窗口创建参数

`createWindow()` 使用 `BrowserWindow`，关键参数如下：

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| width / height | 1380 / 900 | 默认窗口尺寸 |
| minWidth / minHeight | 480 / 460 | 最小尺寸约束（窄窗口下侧边栏收起为图标，各页面按 1240 / 1160 / 820 / 700 / 560px 断点自适应） |
| show | false | 首帧就绪前不显示，避免白屏闪烁 |
| frame | false | 无边框窗口，由渲染层自定义标题栏 |
| backgroundColor | `#F3F7F3` | 与主题背景一致，减少加载闪烁 |
| title | 个人工作台 | 窗口标题 |
| autoHideMenuBar | true | 隐藏默认菜单栏 |
| webPreferences.preload | `join(__dirname, '../preload/index.js')` | 预加载脚本路径 |
| webPreferences.contextIsolation | true | 开启上下文隔离 |
| webPreferences.nodeIntegration | false | 渲染层禁用 Node 集成 |
| webPreferences.sandbox | false | 关闭沙箱以支持预加载能力 |
| webPreferences.spellcheck | false | 关闭拼写检查（中文场景无意义） |

加载策略：存在 `ELECTRON_RENDERER_URL`（开发模式）时加载该 URL，否则 `loadFile(../renderer/index.html)`（生产模式）。

窗口行为：

- `ready-to-show` 事件触发后调用 `show()` 显示窗口；
- `maximize` / `unmaximize` 事件通过 `webContents.send('window:maximized-changed', isMaximized)` 通知渲染层更新按钮图标；
- `setWindowOpenHandler` 禁止应用内新建窗口，`http(s)` 链接交由系统浏览器（`shell.openExternal`）打开，其余一律 `deny`；
- `console-message` 事件将渲染进程日志以 `[renderer]` 前缀转发到主进程输出，便于排查问题。

### 5.3 单实例与异常处理

| 机制 | 实现 | 作用 |
| --- | --- | --- |
| 单实例锁 | `app.requestSingleInstanceLock()` + `second-instance` | 防止多开导致同一数据库并发写入冲突 |
| IPC 异常隔离 | `ipc.ts` 的 `handle()` 包装器 `try/catch` | 单个处理器抛出异常时返回 `{ ok: false, error }`，主进程不崩溃 |
| 数据库驱动回退 | `sqlite-adapter.ts` 的 `openDatabase()` | better-sqlite3 加载失败时回退 `node:sqlite` |
| 退出清理 | `will-quit` → `closeDb()` | 关闭前 checkpoint WAL，避免遗留 `-wal`/`-shm` 脏文件 |

### 5.4 调试截图机制（dev-capture）

`src/main/dev-capture.ts` 提供仅在设置了环境变量 `WORKHELPER_CAPTURE_DIR` 时启用的自动化截图能力，不影响正常启动流程：

1. 读取 `WORKHELPER_CAPTURE_DIR`，未设置则直接返回。
2. 关闭后台节流（`setBackgroundThrottling(false)`），保证被遮挡时动画与渲染仍推进。
3. 在 `did-finish-load` 后依序切换 8 个路由 hash（`01-home`、`02-plan`、`03-module-fitness`、`04-module-english`、`05-news`、`06-review`、`07-stats`、`08-settings`），每页等待后调用 `capturePage()` 保存 PNG。
4. 完成后输出 `CAPTURE_DONE` 并退出应用。

该机制用于 UI 验证（已实测 8 个页面正常渲染）。

## 6. IPC 通信设计

### 6.1 统一响应包装与错误语义

主进程所有处理器经 `ipc.ts` 中的 `handle(channel, fn)` 统一包装：

- 成功：返回 `{ ok: true, data }`；
- 失败：捕获异常，输出 `[ipc] <channel> 执行失败：<message>` 日志，返回 `{ ok: false, error: message }`。

渲染层（`src/preload/index.ts`）中的 `invoke<T>()` 负责解包：当 `res.ok !== true` 时抛出 `Error(res.error ?? '操作失败，请重试')`，因此渲染层各 `window.api` 方法统一以 Promise 成功/失败语义呈现，无需关心包装结构。

### 6.2 通道命名规范

- 采用 `命名空间:动作` 格式，全小写、连字符分隔单词（如 `toggle-maximize`、`create-record`）。
- 命名空间按业务域划分：`win` / `app` / `schedules` / `todos` / `priorities` / `habits` / `modules` / `news` / `reviews` / `stats` / `focus`。
- 主进程 → 渲染层的推送事件同样使用 `命名空间:动作`（如 `window:maximized-changed`）。

## 8. 数据层设计

### 8.1 双驱动适配层策略

`src/main/db/sqlite-adapter.ts` 定义统一的 `SqliteDatabase` 接口（`exec` / `prepare` / `close`），业务层仅依赖该接口，不感知具体驱动。

驱动选择策略（`openDatabase()`）：

1. 优先使用 `better-sqlite3`（性能最佳，随应用打包）；
2. 若加载失败（原生模块未编译/ABI 不匹配），捕获异常并回退到 Node 内置 `node:sqlite`（`DatabaseSync`），输出警告 `[db] better-sqlite3 不可用，已回退到 node:sqlite 驱动`。

两种驱动封装出的 `SqliteStatement` 均提供 `run`（返回 `{ changes, lastInsertRowid }`）、`get`、`all` 方法，保证业务服务调用一致。

| 驱动 | 引入方式 | 触发条件 |
| --- | --- | --- |
| better-sqlite3 | `import Database from 'better-sqlite3'` | 默认首选 |
| node:sqlite | `import { DatabaseSync } from 'node:sqlite'` | better-sqlite3 初始化抛错时回退 |

### 8.2 连接参数

两种驱动在打开时均设置相同 PRAGMA：

| PRAGMA | 取值 | 目的 |
| --- | --- | --- |
| `journal_mode` | WAL | 写前日志，提升并发读与抗崩溃能力 |
| `synchronous` | NORMAL | 在 WAL 下兼顾性能与安全 |
| `foreign_keys` | ON | 启用外键约束（如 habit_logs / module_records 的级联删除） |

### 8.3 数据位置与目录

| 项 | 取值 |
| --- | --- |
| 默认数据目录 | `app.getPath('userData')/data`（即 `%APPDATA%/WorkHelper/data`） |
| 数据库文件 | `<数据目录>/workhelper.db` |
| 重定向 | 环境变量 `WORKHELPER_DATA_DIR`（启动时 `app.setPath('userData', ...)`） |
| 目录自动创建 | `getDataDir()` 通过 `mkdirSync({ recursive: true })` 保证存在 |

### 8.4 迁移机制

`database.ts` 的 `migrate()` 基于 `PRAGMA user_version` 做版本化迁移：

1. 读取当前 `user_version`（无记录则为 0）；
2. 当版本 < 1 时执行 `SCHEMA_V1`（全部建表与索引语句，均含 `IF NOT EXISTS`），随后 `PRAGMA user_version = 1`；
3. 每次启动调用 `seedDefaults()` 写入默认种子数据（幂等）。

迁移采用「只向前、幂等」策略：新版本通过追加 `if (version < N)` 分支扩展，已发布结构不修改。

### 8.5 表结构概览

| `habits` | id | name, icon, target, sort_order, archived | — |

| `modules` | key | key, name, icon, goal, sort_order | — |

### 8.6 种子数据

`seedDefaults()` 在首次启动时按表计数幂等写入：

- 默认习惯 5 项：跑步、英语学习、阅读、多喝水、早起（各含图标与每日目标次数）；
- 默认分类模块 9 项：fitness 减肥运动、english 英语学习、editing 剪辑学习、podcast 播客精选、expression 表达能力、reading 读书推荐、fashion 妆容穿搭、creation 爆款二创、ai AI学习（各含默认目标文案）；
- 默认设置项：`settings.userName = ''`（空昵称）。

### 8.7 事务使用

- **备份恢复**（`settingsService.importBackup`）：以 `BEGIN` / `COMMIT` / `ROLLBACK` 包裹「按外键反向顺序清空业务表 → 按依赖顺序 `INSERT OR REPLACE` 写回」，任一环节失败即整体回滚，保证数据一致性；
- **退出检查点**（`closeDb`）：关闭前执行 `PRAGMA wal_checkpoint(TRUNCATE)`（异常忽略），将 WAL 合并回主库文件；
- 其余单条写操作依赖 SQLite 隐式事务（autocommit）。

### 9.4 主题与设计还原

`src/renderer/src/styles/theme.css` 定义全局设计令牌（CSS 变量），`:root` 提供默认「森林绿」主题取值；多主题通过根节点属性 `data-theme` 切换：

## 11. 性能与可靠性设计

### 11.1 性能优化点

| 优化点 | 实现 | 收益 |
| --- | --- | --- |
| 消除白屏 | 窗口 `show: false` + `ready-to-show` 后再显示，`backgroundColor` 与主题一致 | 首帧呈现更平滑，冷启动体验更佳 |
| 数据库预初始化 | `whenReady` 阶段即调用 `getDb()` | 完成迁移与种子写入，缩短首次操作等待 |
| 并行查询 | 渲染层 `appStore.init()`、`planStore.load()` 使用 `Promise.all` 批量请求 | 减少 IPC 往返总耗时 |
| 按需路由加载 | 路由组件使用动态 `import()` 懒加载 | 降低首屏渲染体积 |
| 免第三方图表库 | `MiniBarChart`、`StatsLineChart` 纯 SVG 自绘 | 减小包体与运行时开销 |
| 查询上限 | 记录/笔记/资讯/复盘列表 `LIMIT 500`，trend 仅取 N 天 | 避免大数据量下的渲染与传输压力 |
| 定时器隔离 | 专注计时仅在卡片挂载时启动 `setInterval`，卸载时清理 | 避免后台持续耗电 |
| 调试节流 | 仅在截图调试时 `setBackgroundThrottling(false)` | 正常运行时保持默认节流，节省资源 |

### 11.2 可靠性与数据安全

| 机制 | 实现 | 作用 |
| --- | --- | --- |
| WAL 模式 | `journal_mode = WAL` | 提升写入性能与崩溃恢复能力 |
| 索引 | 各 date / module_key / habit_id 建立索引 | 加速按日期与模块的查询 |
| 外键级联 | `habit_logs` / `module_records` / `module_notes` 声明 `ON DELETE CASCADE` | 删除父实体自动清理子数据 |
| 唯一约束 | `habit_logs UNIQUE(habit_id, date)`、`reviews.date UNIQUE` | 保证每日打卡/复盘唯一，幂等 upsert |
| 退出清理 | `will-quit → closeDb()` 执行 WAL checkpoint | 避免遗留脏日志文件，保证下次正常打开 |
| 事务保护 | 备份恢复用 `BEGIN/COMMIT/ROLLBACK` | 恢复失败不留半成品数据 |
| 错误集中处理 | IPC 包装器返回 `{ ok: false, error }`，预加载抛出 Error，渲染层 Toast 提示 | 异常不崩溃、用户可感知 |
| 单一数据源刷新 | 写操作后 `load()` / `refreshStats()`，toggle 本地替换 | 界面与数据库状态保持一致 |

## 12. 可扩展性设计

新增一个业务模块（如新增一类可打卡的学习内容）遵循固定的六步链路，各层职责边界清晰、互不越界：

| 步骤 | 位置 | 内容 |
| --- | --- | --- |
| 1. 定义类型 | `src/shared/types.ts` | 新增实体接口（如 `Xxx`）与输入类型（`XxxInput = Omit<Xxx, 'id' | 'createdAt'>`） |
| 2. 编写服务 | `src/main/services/xxx.service.ts` | 基于 `SqliteDatabase` 实现增删改查（全参数化 SQL），并在 `db/database.ts` 迁移中加表与索引 |
| 3. 注册 IPC | `src/main/ipc.ts` | 使用 `handle('xxx:list', ...)` 等注册通道，返回类型在共享类型中约定 |
| 4. 暴露 API | `src/preload/index.ts` | 在 `api` 对象中新增 `xxx` 分组，封装 `invoke<T>('xxx:...')` |
| 5. 创建视图/状态 | `src/renderer/src/views/XxxView.vue`、`stores/xxx.ts` | 视图渲染与交互，store 封装 `window.api.xxx.*` 调用与刷新 |
| 6. 配置路由/导航 | `src/renderer/src/router/index.ts`、`components/AppSidebar.vue` | 新增路由记录与侧边栏入口 |

扩展约束：

- 分层不可穿透：渲染层不得直接调用 IPC 或访问数据库；
- 契约先行：通道参数与返回类型必须先在 `src/shared/types.ts` 声明；
- 迁移只增不改：数据库结构变更通过新增 `user_version` 分支实现；
- 复用共享纯函数：日期、进度、统计口径统一走 `src/shared/logic.ts`，避免多处理。
